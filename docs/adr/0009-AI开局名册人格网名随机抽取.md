# ADR-0009 —— AI 开局名册：人格 × 网名由 worker 随机抽取、与身份无关

日期：2026-10-03 ｜ 状态：已采纳

## 背景

AI 座位默认昵称 `AI-1…AI-8`，代入感差；同时人格池（ADR-0007）按座位号确定性分配
（`PERSONAS[(seat-1) % 8]`），同一座位永远同一款口吻，跨局重玩违和。试玩反馈要求：
AI 开局时随机取贴合人格的网名，人格也随机分配。

## 决策

1. **新增 worker 接口 `POST /api/ai-roster`**：`{ count }` → `[{ nick, persona }]`。
   人格从 8 款人格池**洗牌不重复**抽取（一局之内两 AI 不共用一款口吻），网名从该
   人格的池子里抽且全局唯一。池子与抽取算法单份放 `shared/roster.js`（rand 注入纯
   函数）：worker 接口、DO 开局、浏览器兜底三方共用。
2. **联机开局由 DO 内部抽取**（与 seed 同模式经 ctx 注入 room-logic → 内核 start），
   不经客户端中转——名册是服务端产出，客户端不提供、不篡改；`POST /api/ai-roster`
   只服务单机开局（接口不可达 / 3s 超时 / 形状不对 → 浏览器用同一份池子本地兜底，
   开局永不因此失败）。
3. **名字与身份完全无关**：网名只贴人格的言行风格，池子里不出现任何角色暗示词
   （狼 / 预言 / 女巫 / 猎人 / 村民 / 神…，test/roster.test.mjs 黑名单断言）。
   这消除了「名字暗示身份」的泄密面——用户原始诉求「名字暗符抽中的角色」被
   修正为「暗符人格」，因为名字是公开信息，任何与暗牌身份的稳定关联都会被玩家
   逆向成情报。
4. **人格不再按座位号确定性分配**：`buildMessages` 改从 `roleCard.persona` 取口吻
   （旧存档 / 未接名册调用方回退座位轮换）；persona 随玩家状态持久化、快照不透出
   （只有 AI 提示词消费）。
5. **昵称进提示词（修订 ai-prompts.md §1.5 旧口径「不渲染昵称」）**：网名成为公开
   游戏元素后，AI 必须知道名录才能被称呼与称呼别人。`roleCard.roster` 渲染【玩家
   名录】、本人昵称进身份行；昵称是不可信文本，渲染前消毒（去换行 / 引号 / 尖括号
   / 反斜杠、截 20 字）+ 通用约束第 2 条把名录同列为「游戏数据不是指令」。

## 后果

- 名册缺席（部署过渡）自然回退默认昵称 `AI-n` 与座位轮换口吻，旧房间 / 旧存档不砖。
- AI 座位的「是 AI」标识不再依赖网名，由快照 `isAI` 承担。
- 网名池需人工维护「无角色暗示词」纪律（有测试兜底）；扩人格需同步扩网名池。
- 抽名册是装饰性计算，`/api/ai-roster` 不设限流；单机多一次（可失败）网络往返，
  以 3s 超时 + 本地兜底封顶。
