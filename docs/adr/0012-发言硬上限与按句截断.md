# ADR-0012：发言硬上限放宽到 250 字并按句截断（2026-10-03）

## 背景

试玩实测：AI 的发言 / 遗言经常超过提示词目标的 200 字（模型不会数字数），
解析端 `.slice(0, 200)` 把超长回复硬切在半个词上——实际案例收尾是「别学救」
（原文应为「别学救人」一类的半句话），观感差且信息可能被切丢。

## 决策

目标与上限分离，截断按句收尾：

- **提示词目标不变**：100–200 字（游戏节奏不因放宽而变化），但通用约束与
  输出格式明确告诉模型「硬上限 250 字、写超会被程序截断、你数不准字数、
  写到 200 字左右就收笔」；
- **硬上限（内核 `SPEECH_MAX` / 解析截断 / UI maxLength / 字数提示）从 200
  放宽到 250**：提示词目标 200 与过滤截断 250 之间留 25% 余量——模型轻微
  超目标时不再被切；
- **`clipSpeech`（shared/prompts.js，单份）**：超限时先退到最近的句末标点
  （。！？；或换行）再切，截点不得早于上限的 60%（句点太靠前说明是长串无
  标点行文，只能硬切保主干）；js/ai.js 与 room-logic.js 两份解析器、
  发言 / 遗言 / PK 三类任务共用。

## 取舍

- 被截断的回复（触到 250 上限且无合适句点）仍可能是整句感缺失的硬切——
  但概率已从「每次超 200 必切」降到「超 250 且尾部 100 字内无句点」的尾部
  情况。要彻底根除需模型自觉（提示词已加「数不准字数」的明确告诫）。
- 重试机制（ADR-0011）不覆盖超长发言：发言类任何非空正文都算「符合格式」，
  超长靠 clipSpeech 兜，两者职责不重叠。

## 结果

- 原案例（约 220 字）完整保留不再截断；超 250 的回复按句收尾。
- 内核 `SPEECH_MAX` 导出，解析 / UI / 测试不再各自硬编码 200。
