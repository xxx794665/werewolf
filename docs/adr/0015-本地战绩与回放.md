# ADR-0015：本地存档 / 对局回放 / 战绩统计

日期：2026-10-05。状态：已采纳（features.md §5 / §6 / §7 已同步）。

## 背景与决策

非目标 §13.6「战绩统计、天梯、历史对局回放」。用户四问定盘选**本地存档全套**（推荐档：纯客户端，不动服务端存储）。决策：

1. **落档**：终局（revealed）自动把对局记录存 localStorage 单键 `ww_archive`（数组，上限 30 条超出丢最旧，Quota 异常减半重试，失败静默——同 ww_solo 口径）。单机在 soloDrive 终局转移时落档；联机在收到 revealed 快照时落档（快照即终局全量视图：players 全员亮身份带 role/death、events = 房间公开日志全量）。id 幂等：`solo:{seed}` / `online:{code}`——会话内 Set + mergeArchive 按 id 去重双层；boot 恢复到的旧终局也补落档，刷新恢复 / 重复进入终局屏不重复入档。
2. **记录形状**（v1）：`{ v, id, ts, mode, board:{id,name}, winner, reason, day, players:[{seat,nick,isAI,role,death?,won}], log }`——`won` 按 `isWolf` 判阵营胜负（狼王计狼侧）；log 为 t-schema 全量公开事件。**夜间私有信息（刀口决策过程 / 验人历史 / 密聊）不进回放**——公开日志 + 终局身份即复盘全量。
3. **UI**：主菜单「战绩与复盘」→ 对局列表（日期 / 板子 / 模式 / 天数 / 胜方）+ 顶部战绩汇总（aggregateStats 按昵称聚合局数 / 胜率 / 角色分布，**排除 AI 座位**；「我」按当前昵称弱匹配高亮，同名不同人会一并高亮——已知弱口径）。复盘详情 = 只读视图：全员身份网格（role + death + won）+ 按天折叠日志（复用 groupLogEvents）+ 投票记录卡（复用 voteHistory，含竞选轮次与 1.5 票权重）。
4. **实现落点**：新模块 `js/archive.js`（纯函数 buildArchiveRecord / mergeArchive / aggregateStats + localStorage 薄 I/O，node --test 可测）；`won` 判定复用 `shared/game.js isWolf`。

## 后果

- 非目标 §13.6 解冻为**本地口径**；服务端归档、天梯、跨设备战绩仍是非目标（uid 本就本机）。
- `js/archive.js` 进 sw SHELL 清单（v21）；功能上线前的对局无存档属预期。
- 单键 30 条按「一条整局公开日志 ~50–150KB」估算，总占用在 5MB localStorage 配额内。
