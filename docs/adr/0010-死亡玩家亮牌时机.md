# ADR-0010：死亡玩家亮牌时机——遗言提交后才进观战视角（2026-10-03）

## 背景

features.md §7.8 原口径「死亡玩家进入观战视角，可见全员身份」没有定义时机：
快照裁剪实现为「一旦死亡即透出全员 role」。试玩实测暴露问题：玩家白天第一轮
被投票出局、正要输入遗言时，座位网格上全员身份已经亮开——死者还"在场"（遗言
是当场玩法的一部分），此时亮牌既穿帮也毁体验（暗牌局中途看到狼底就没悬念了）。

## 决策

亮牌时机后移到「本人的最后动作提交完」：

- 死亡但**还有待提交行动**（首夜遗言 / 放逐遗言 / 猎人开枪，即 `pending === 本人座位`）
  → 仍按暗牌口径，只看自己的身份；
- 行动提交完（队列走完 / 开枪结算）→ 进入观战视角，可见全员身份（仅自己可见，
  原 §7.8 口径保留）；
- 终局 `revealed` 全员亮牌不变。

实现上只是快照裁剪的 spectator 判定加一个条件（`pending !== seat`），
`worker/src/room-logic.js` 与 `js/app.js`（单机同形快照）两处同口径。

## 取舍

- 第一夜多死时，后遗言者在前者发言期间就能看到全员身份（只要不是自己的行动
  回合）——按「输入遗言时不得亮牌」的字面口径收窄，不做逐人门控；观战者本就
  无法再影响对局，提前看到不构成信息泄漏通道（快照仅本人可见）。
- 不回溯已开局房间：旧快照口径随下次提交自然翻到新口径，无迁移成本。

## 结果

- 被放逐玩家输入遗言期间只看到自己的身份卡；提交遗言后立即全员亮牌观战。
- `snapshotFor` 的 rev 对比自然覆盖该变化（受影响座位 rev+1），无需额外迁移。
