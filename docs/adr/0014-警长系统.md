# ADR-0014：警长系统（完整）

日期：2026-10-05。状态：已采纳（features.md §4.2 / §5 已同步）。

## 背景与决策

非目标 §13.2 含「警长系统（上警 / 撕警徽）」。用户四问定盘选**完整警长**：恒开启（四个板都带警长玩法）、单机与联机同批支持（同一内核）。决策：

1. **竞选时序**：day 1 唯一一次，插在首夜遗言之后、常规发言之前：`elect_join`（全员按座位序表态上警 / 不上警）→ `elect_campaign`（候选人按序竞选发言）→ `elect_withdraw`（候选人按序表态退水）→ `elect_vote`（投票人 = 存活、非候选人、非翻牌白痴；可弃票）→ 平票进 `elect_pk_speak` + `elect_pk_vote`（投票人不变）→ 再平 / 全弃 → 本局无警长。0 人上警 / 全退水 → 无警长；唯一候选人 → 直接当选；全员上警（无投票人）→ 无警长。竞选表态 / 发言 / 票向 / 结果均为公开事件。
2. **票权**：警长在主投票 / PK 投票中票算 **1.5 票**（0.5 为二进制精确值，累加无浮点误差；狼队定刀票不加权）。
3. **警徽流**：警长死亡落账处（夜结算死亡循环 / 放逐 / 枪杀目标）即时置 `s.badge = { pending }`；三个闸口拦截处置：白天主链入口（next='day'，覆盖夜死与走完遗言链的被枪杀警长）、放逐遗言后（next='exile'，**警徽先于猎人 / 狼王翻牌**）、入夜前（next='night'，覆盖白天被枪杀直接进夜的场合）。`badge_move { seat, target }`：移交给存活玩家（新警长继承 1.5 票）或撕毁（target=null，本局无警长）；警徽去向是公开事件。终局（gameOver）不处置警徽。
4. **事件 / t-schema**：新公开事件 `elect_run / elect_speech / elect_withdraw / elect_vote / sheriff_result（kind: elected|none|no-voters|tie-pk|transfer|destroy）/ badge_move`；t-schema `t:'sheriff'`（badge 并入 kind transfer/destroy，带 from/to）；竞选中 `sheriff_result{kind:'tie-pk', pk}` 携带 PK 台名单。
5. **AI 提示词**：PHASES 增 6 个竞选值（elect_join / elect_withdraw / elect_campaign / elect_pk_speak / elect_vote / badge）；输出格式：上警 `run/pass` 二选一、退水 `quit/stay` 二选一、警长票与警徽为座位号或 `skip`（badge 的 skip = 撕毁）；`roleCard` 增公开字段 `sheriff`（当前警长座位，roster 同款公开先例）与竞选中 `election = { candidates, pk }`；buildMessages 在「当前局面」注入警长与 1.5 票提示；历史窗口 digest 为 `t:'sheriff'` 保留一行摘要（老天数 AI 才推得出警长与票权，elect_* 明细压缩丢弃可接受——竞选仅 day 1）。
6. **两处刻意简化**（对经典规则的收窄，ADR 记录在案）：警长**不**决定发言顺序（维持座位序）；全员上警不做候选人互投（直接无警长）。

## 后果

- 非目标 §13.2 警长部分解冻；快照新增公开字段 `sheriff` / 竞选中 `election`（警长身份全程公开含夜里——竞选只在白天，§4.1.6 夜冻结不涉及）。
- `tally` 支持浮点票重（vote_result.tally 数量可为 1.5）；投票记录卡（§5.14）把竞选轮次纳入按天分组并按日志 sheriff 事件推警长座位计 1.5 权重。
- 放逐链顺序定为「遗言 → 警徽 → 翻牌枪」；回退口径：badge=撕警徽、join=不上警、withdraw=留下、竞选发言=兜底句、警长票=随机候选（无可投则弃票）。
