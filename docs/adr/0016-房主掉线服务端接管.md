# ADR-0016：房主掉线服务端闹钟接管

日期：2026-10-05。状态：已采纳（features.md §5.11 / §7.7 已同步）。

## 背景与决策

房主掉线时联机 AI 座位停摆：`drive_ai` 锁房主（room.js uid 校验），只能靠 150s 行动超时确定性回退（退化，不是真 AI），房主失联 30 分钟房间作废（§13.14 口径）。根因很窄：AI 驱动全链路（组提示词 → 出站 → 解析 → 提交）本就在 DO 内，且服务端有体验通道默认 key——**卡点只是触发权**。用户四问定盘选**服务端闹钟接管**（推荐档，不解冻「房主转移」）。决策：

1. **接管条件**（`alarmDriveDue(room, now)` 纯函数）：联机中（HUMANS>1）房主失联（35s 在线窗口）且当前待行动座位是 AI / 托管 → DO alarm 以 **5s 节拍**驱动该座位。房主心跳恢复即假、节拍自然停（房主客户端 4s 兜底节拍照常驱动）。
2. **driveSeat 共享内核**（room.js 重构）：HTTP `drive_ai` 与 alarm autoDrive 走同一出站 / 解析 / 提交管线；HTTP 路径语义一字不差（45s+25s 两次尝试、失败立即确定性回退）；alarm 路径**单次 25s 尝试**、cfg = 体验通道（DEFAULT_AI_BASE + cline-pass/deepseek-v4.1-flash，key 走 env.DEFAULT_AI_KEY 注入，与 ai-proxy 同口径）、**失败不立即回退**（下拍重试，150s deadline sweep 是最终兜底——通道彻底不可用时游戏退化为回退，不砖）；两路径经 `this.driving` 互斥。
3. **作废口径修订**：房主失联 30min 作废 → **全员失联 30min 作废**（任何真人 30 分钟内心跳出现过即不作废；`latestHumanSeen` 纯函数与 sweep / nextAlarmAt 共用）——房主一人掉线不再砖房，他人还在就照常推。
4. **防热循环（关键工程细节）**：nextAlarmAt 的作废分量连根改 `latestHumanSeen + 30min`——旧公式 ownerSeen+30min 在房主久掉线而他人在线时会算出**过去时刻**，被 `Math.max(now+1,…)` 钳成毫秒级 alarm 重排、烧 CF alarm 配额（worker 测试有防回归用例：房主失联 >30min 但他人有心跳 → 下一 alarm 时刻必须 > now）。alarm() 末尾的 arm 也基于 autoDrive 之后重读的房间。
5. **快照**：`waitingOwner` 更名 `serverDrive`（同条件：!ownerOnline && 对局中 && pending 为 AI / 托管），文案改「房主暂时掉线，AI 已由服务端自动接管」。

## 后果

- **§13.14「不做房主转移」维持**——本方案不转移房主身份，ADR-0002 的 ai_view / 触发权口径不动；仅把「房主失联 30 分钟作废」条款改写为全员口径。
- 已知取舍：房主配了自有 BYO key 时，掉线期间 AI 质量回落到体验通道（key 只瞬态随请求、服务端无从取用）；闹钟驱动的出站成本上限约 12 次 / 分钟（DO alarm 计费口径内）。
- §5.11 语义不变：150s 行动超时与确定性回退仍是最终兜底，接管只是把「等死」变「照常推」。旧部署房间（waitingOwner 字段时代）过渡：UI 判空容错，不阻塞。
