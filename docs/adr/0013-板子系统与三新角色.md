# ADR-0013：板子系统与三新角色（狼王 / 守卫 / 白痴）

日期：2026-10-05。状态：已采纳（features.md §3 / §4.1 / §5 已同步）。

## 背景与决策

第一版口径是「唯一板子、9 人固定」（ADR-0001，非目标 §13.2）。用户解冻玩法包需求，四问定盘选「三板全做」：加狼王 / 守卫 / 白痴三板，连同标准板共 4 种玩法可选；**人数恒 9 不变**（可变人数仍是非目标）。决策：

1. **BOARDS 注册表**（`shared/game.js`）：`{ id: { name, intro, roles } }` 四板；`start` 动作新增可选 `board` 参数（非法拒绝、缺省 `standard` 兼容旧客户端 / 旧房）；发牌牌堆按 `BOARDS[board].roles` 展开；状态落账 `s.board` / `s.seed`（存档、回放、测试复现用）。单机屏与联机大厅（仅房主）各一个板子选择卡，介绍文案取自注册表（UI 不复制文案）。
2. **isWolf 判狼收口**：导出 `isWolf(role)`（狼人 | 狼王），全仓 `role === 'werewolf'` 判狼字面量统一替换——狼队长池、胜负 parity、狼队密聊与定刀权限、验人结果全与狼人同口径。唯一刻意例外：夜死猎人翻牌判定保持 `role === 'hunter'` 精确匹配（狼王夜死无枪）。
3. **狼王**：仅被放逐时翻牌开枪带走一人（复用猎人枪管线：`pendingHunter` + `day:hunter`）；被刀 / 被毒 / 被枪杀不发动。`hunter_flip / hunter_shoot` 事件增可选 `role: 'wolfking'` 字段（普通猎人省略，旧事件形状不变）；t-schema `t:'hunter'` 同步带可选 role。
4. **守卫**：夜顺序改为 **狼定刀 → 守卫 → 预言家 → 女巫 → 结算**（enterGuard 插在 resolveWolfVote 后，守卫死亡或不在板时跳过）。`guard_protect { seat, target }`：目标必须存活（可守自己）、不可与上一晚守护同一人（`s.guard.last` 持久）、必须选人（不可空守）。结算（奶穿语义）：守护且未救 → 活；守护且救 → 死（奶穿，cause='blade'）；未守护且未救 → 死；毒药无视守护恒死。
5. **白痴**：纯被动。被放逐时翻牌免死（`vote_result` 增可选 `idiot: true`，t-schema `t:'exile'` 增 `idiot` 且不计入死亡推导），置 `p.idiotRevealed`；已翻牌后再被放逐同口径免疫。失去投票权（`votersOf` = 存活且非翻牌白痴，用于 hVote / pendingSeat / tally / 回退兜底），保留发言权；夜间被刀 / 毒 / 枪杀为普通死亡；计入好人 parity。
6. **提示词**：`BOARD_RULES` 静态常量改为 `boardRulesOf(boardId)` 按板动态生成（构成句 + 在场角色专项规则句 + 夜顺序句插守卫位 + 警长规则句）；`roleCard` 增公开字段 `board`；`ROLE_PROMPTS` / ROLES 白名单加三角色。

## 后果

- 非目标 §13.2 板子 / 扩展角色 / 警长部分解冻（**可变人数房间、长老 / 混血儿等更多角色仍是非目标**）；ADR-0001「可变板子延后」就此兑现。
- 部署过渡：旧持久化房间 / 旧单机存档无 board / guard / sheriff 字段——hStart 开局前补齐（同 wolfChatLog 兜底模式）、night 无 guardTarget 时守护恒 false（旧局语义不变）、UI 侧判空容错；已实证（旧态剥离驱动 + 整局 e2e 用例）不需要 advance() 级回填。
- 快照新增公开字段 `board`；acceptance 快照字段白名单探针同步。
- 三新角色 ×（内核 / 提示词 / 双解析器 / 前端 / 测试）五层触点全部落地；`node --test` 从 113 增至 181。
