# ADR-0011：AI 行动重试 1 次与 75s 时间预算（2026-10-03）

## 背景

试玩反馈：兜底语料（「目前没有特别的线索，先不站边。」）出现概率偏高。排查
旧实现有两个成因：

1. **重试只盖住「请求失败」，盖不住「回复不合格」**：`requestChat` 内部两次
   尝试只重试网络层失败 / 空正文；正文非空但解析不出合法动作（投票阶段回了
   一段话、目标座位已死等）直接走确定性回退，白白丢掉一次本可成功的机会。
2. **总耗时无界**：单次尝试超时 90s × 2 = 最长 180s，超过 DO 行动超时 150s
   的一半——联机时 DO 的 150s alarm 会先执行确定性回退，房主驱动拿到回复时
   座位已被回退顶掉（STALE）；单机则是玩家对着「轮到 X 号」干等三分钟。

## 决策

重试口径改为按「结果」而非「传输」判定，且总预算封顶：

- 第一次请求失败（超时 / 非 200 / 空正文）**或未回复符合格式的回复**
  （解析不出动作，或解析出的动作被内核干跑校验拒绝——目标已死 / 非队列头 /
  PK 台外等）→ 重试 1 次；
- 两次尝试超时 **45s + 25s = 70s < 75s**（一轮 150s 的一半，用户口径）；
  不等长是有意的：第一次尽量盖住思考型模型 30–60s 的流式出文窗口，第二次
  只需兜住瞬失败（5xx / 断流 / 空正文都是秒级返回）；
- 截断放宽预算（finish=length / 伪 500 → max_tokens ×2）保留，但占用该次
  重试名额；
- 常量收敛到 `shared/prompts.js`（`AI_ATTEMPT_TIMEOUTS_MS` / 
  `AI_STEP_BUDGET_MS`），单机（js/ai.js decideFor）与联机（drive_ai）同源；
  解析 + 干跑校验逻辑两份各自持有（同 ADR-0004 漂移口径）。

## 取舍（真实代价，后人须知）

- **超过 45s 才出的慢回复会被掐**：思考型模型若单次需要 >45s，第一次尝试
  必超时、25s 的重试也救不回——这类配置会更多走回退。这是用户为「等待有界」
  明确买下的取舍；BYO 用户若上游慢，调大 max_tokens 无济于事，只能换更快
  的上游。
- `/api/ai-proxy` 路由的超时上限（90s）不动：浏览器侧已用 AbortController
  按 45s/25s 主动断开，路由上限只是传输层兜底（测试连接用 60s 探活仍需它）。

## 结果

- 单个 AI 行动最长 ~70s（含回退提交余量 75s），一轮 150s 内必然完成；
  联机 drive_ai 不再与 DO alarm 赛跑，单机等待可预期。
- 单机模式以 `AI_STEP_BUDGET_MS` 为 AI 行动倒计时数据源（吸顶状态条白天可见），
  倒数到 0 即回退提交，倒计时与真实行为一致。
