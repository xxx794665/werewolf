## 0. 一句话定位

单机 / 联机狼人杀网页应用：移动端优先的零构建静态站 + Cloudflare Workers 房间后端；单机 = 1 真人 + 8 个 LLM 扮演的 AI；联机 = 房间制 + AI 补位。

## 1. 平台与移动端硬指标（验收级）

- 纯静态、零构建、无框架：原生 HTML/CSS/JS，直接推 GitHub Pages，不经过 CI。
- 移动端优先（母本口径照抄）：`pointer:coarse` 下触控热区 ≥ 44px；单列布局，大屏正文限宽 ~640px；最小字号 ≥ 12px；弹窗禁用 from-opacity 入场动画（透明拦截点击）；flex 防压瘪。
- 顶栏吸顶 + 滚动收拢。
- **吸顶状态条**：对局中阶段条常驻吸顶在顶栏正下方随页面滚动（`--topbar-h` 实测跟随收拢），显示阶段（第 N 天/夜）+ 白天子阶段 + 轮到谁（轮到本人显示「轮到你」）+ 行动倒计时（仅联机白天，数据 = 快照 `deadline {at, seat}`，§5.11；夜里不透防泄漏轮到谁，单机无超时无倒计时）。
- PWA：`manifest.webmanifest` + `sw.js`（HTML/CSS/JS network-first，图片字体 cache-first，CACHE 版本号 `werewolf-vNN` 递增）。
- 全站零 emoji，图标一律 SVG；单一 `style.css`。
- 走查验收：360 / 390 / 844×390 / 834 / 1024 / 1366 视口 × 全部屏幕，无横向溢出、无遮挡、热区达标。
- **不可逆操作两步确认**：定刀、解药、毒药、开枪、投票、PK 投票、开始游戏一律「先选择 → 底部固定确认条（热区 ≥44px）→ 再提交」，防触控误触毒错人 / 开错枪。
- 仅中文，不做出多语言（非目标）。

## 2. 总体架构（照母本，详见 ADR-0001）

- 前端：GitHub Pages，预计地址 `https://xxx794665.github.io/werewolf/`。
- 后端：Cloudflare Workers + Durable Objects（SQLite 后端），**一个房间 = 一个 DO 实例**，DO = 游戏状态机与唯一权威。
- 通信：HTTP 短轮询 `POLL_MS = 1500`；**`rev` 是按座位视角各自计算的游标**（不是全局游标）——每个座位只能看到自己视角内的事件流，`rev` 反映该视角的版本；无变化只回 `unchanged`（几十字节）。**夜里非行动、非知情座位视角冻结**（连续回 `unchanged`，快照停在 `night_N` 不显示子阶段推进），行动者本人轮到时视角更新；**天亮结算时全员 `rev` 一次性齐跳并公布死者**——因此观察者无法从「谁在夜里被轮到」推出预言家 / 女巫是否存活。页面回前台先 300ms×4 次追赶轮询；断线重连靠 localStorage 固定身份（uid + 昵称）。
- 轮询退避（控成本）：连续 5 次 `unchanged` 后退避至 4000ms，快照任何变化立即恢复 1500ms。夜里多数座位与等待他人行动的阶段会自然落入退避档；9 人全活跃白天保持 1500ms。
- **单机模式 = 浏览器本地执行**（ADR-0003）：同一份 `shared/game.js` 内核在玩家浏览器本地跑（1 真人 + 8 AI，`start(solo:true)` 本地开桌），不建 Worker 房间、不经 DO；对局状态存 localStorage，刷新可恢复。不存在第二套游戏逻辑（单机 / 联机共用同一内核）。
- 游戏内核（板子定义、胜负判定、流程推进、行动超时与确定性回退）是 `shared/` 下单份纯函数模块，DO 与前端共同 import（ESM，根 `package.json` 已设 `"type":"module"`）。
- 快照按请求者座位裁剪私有字段（§8.1）。读 AI 私有视角的接口是 owner 专属动作 `act(action=ai_view, seat=N)`（§9，ADR-0002）：仅房间 owner 可调用，且目标座位限定为 AI 座位或处于 AI 托管状态的座位。除此之外没有任何接口能拿到他人座位视角。联机 AI 驱动自 ADR-0003 起走服务端 `drive_ai`，不再依赖该接口（保留实现）。
- AI 决策发起路径（ADR-0003）：**单机**由玩家本人浏览器发起（BYO Key 经 `/api/ai-proxy` 透传），结果直接提交本地内核；**联机**走服务端发起 `act(action=drive_ai)`——房主浏览器触发并随请求透传 BYO baseUrl / model / key（不落盘），DO 组装提示词、url-guard 出站、结果写回状态机，失败走确定性回退。DO 对每阶段每座位幂等（重复提交忽略）。

## 3. 角色与板子（唯一板子，9 人固定）

| 座位角色 | 阵营 | 数量 | 技能（口径定死） |
|---|---|---|---|
| 狼人 | 狼 | 3 | 每夜狼队密聊后投票定刀口（见 §4.1.1 / §5.1）；狼互相知道队友 |
| 平民 | 好 | 3 | 无技能，白天发言与投票 |
| 预言家 | 好 | 1 | 每夜验 1 名存活玩家，得知「好人 / 狼人」 |
| 女巫 | 好 | 1 | 解药、毒药各全局 1 瓶；同晚至多用 1 瓶 |
| 猎人 | 好 | 1 | 出局时可翻牌开枪带走 1 名存活玩家（见 §5.6） |

- 房间人数**固定 9，不可设置**（对需求「房间设置人数」的刻意收窄，理由见 ADR-0001）。
- 发牌：开局 DO 内均匀随机洗牌。
- 死亡玩家不翻牌（暗牌）；猎人翻牌是唯一亮身份时机。游戏结束（revealed）全员亮牌复盘。

## 4. 昼夜流程状态机（DO 内，逐条定死）

阶段序列：`lobby → night_1 → day_1 → night_2 → day_2 → … → revealed`。

### 4.1 夜晚（night_N，子阶段固定顺序）

1. **wolf（§4.1.1）**：狼队密聊 → 全员投票定刀。**密聊**：只有存活狼人可见的夜间频道（`night.wolfChat`），每人每晚至多 5 条、每条 ≤60 字，天亮即清空，不产生公开事件；**投票**：每个存活狼人一票（不可改票，目标必须是存活玩家——允许投队友 / 自己，自刀与弃车合法），全部存活狼投完的瞬间结算：最高票出局，平票由狼队长一锤定音（队长的票在平票集合中则从其票，否则取最小座位号）。所有存活狼人当晚均知晓刀口。
2. **seer**：预言家验 1 名存活玩家（不得验已死、不得验自己），结果记入预言家私有信息。
3. **witch**：女巫看刀口（仅解药未用时可见；用掉后不再显示刀口）→ 三选一：解药救刀口 / 毒药毒 1 名存活玩家 / 跳过。**首夜可自救，之后不可自救；同晚至多 1 瓶药**。
4. **结算**：死亡 = 刀口（未被救）∪ 毒目标，可重合（重合死 1 人）。天亮一次性公布全部死者（不区分先后）。平安夜 = 刀口被救且无毒。
5. 猎人无夜行动；夜晚不产生公开消息。
6. **夜里可见性（防泄漏，硬性）**：夜子阶段推进对非行动座位不可见——快照只显示 `night_N`，不显示轮到谁。每个座位夜里视角更新仅限本人合法可知：行动者看到「轮到你行动」、存活狼看到密聊频道 / 狼票 / 刀口、预言家看到验人结果、女巫看到刀口（§4.1.3）。**狼队密聊与狼票字段只出现在狼座快照**，非狼座位与死者快照一律不带。任何人不得从快照推断其他座位是否存活 / 是否已行动。天亮结算一次性全员齐跳公布死者。

### 4.2 白天（day_N，子阶段固定顺序）

1. **announce**：公布死者（不翻牌）。
2. **night_hunter**（如触发）：当夜死者中有「可开枪的猎人」（死于刀口、未死于毒，见 §5.3）→ 翻牌亮猎人身份 → 选择带走 1 名存活玩家或放弃开枪 → 开枪则枪杀目标即刻死亡并**追加公布**（被枪杀者无遗言、不翻牌）→ 即时判胜负（§5.7），分出胜负则整局结束。**本步先于遗言**。夜死猎人自己的遗言（仅首夜，§5.4）在其翻牌开枪之后发表。
3. **遗言**：**首夜死者有遗言**（各补 1 条，≤200 字，夜死猎人在第 2 步后）；非首夜夜晚死亡无遗言；被枪杀者无遗言。
4. **speak**：从存活最小座位号开始，按座位顺序轮流发言，每人 1 条 ≤200 字，不可插话、不可跳过（AI 与真人同规）。
5. **vote**：全部存活者投票（1 人 1 票，可弃票），**逐人投票去向公开展示**。
6. **exile**：最高票者出局 + 遗言（≤200 字）。平票 → 平票者进入 `pk_speak`（各 1 条 ≤200 字）→ `pk_vote`（存活者只能在 PK 台上的人里投票）→ 再平或全弃 → **无人出局**（「平安日」）。
7. **hunter**（如触发）：被放逐者是猎人 → 翻牌亮身份 → 选择带走 1 名存活玩家或放弃开枪（被枪杀者无遗言、不翻牌）。
8. **判定胜负**（见 §5.7），未分胜负进入下一夜。

### 4.3 即时胜负检查点

每次死亡结算后（夜结算 / 放逐 / 猎人枪）立即判胜负，达成立刻进入 `revealed`，剩余阶段不再执行。

## 5. 关键口径速查（写代码前逐条对齐）

1. **狼队长**：存活狼中「真人优先（多人取座位号最小），否则座位号最小 AI 狼」。定刀改为全员投票后，队长的职责是**平票裁定**（见 §4.1.1）。
2. **女巫**：解药毒药各 1 瓶全局；同晚至多 1 瓶；首夜可自救；解药耗尽后不再看刀口。
3. **毒死猎人不可开枪**：夜结算中猎人死于毒（即使同时被刀）→ 无枪；仅死于刀 / 放逐 → 可枪。夜死猎人的开枪槽位在白天 announce 之后、遗言之前（§4.2.2）。
4. **遗言**：首夜夜死有；非首夜夜死无；被放逐有；被枪杀无。
5. **暗牌**：任何死亡不亮身份，猎人翻牌与终局复盘除外。
6. **猎人枪**：可放弃；枪目标必须存活；枪后立即再判胜负。
7. **胜负（屠城制）**：狼存活数 = 0 → 好人胜；狼存活数 ≥ 非狼存活数 → 狼胜。
8. **发言**：严格按座位顺序、每人每轮 1 条、**≤200 字**（UI 与提示词双重限制）；无自由插话。
9. **投票**：全员逐人去向公开；全弃票等同平票（无人出局）。
10. **狼不可空刀**：保证每夜有刀口，游戏必收敛。
11. **行动超时 150s**：DO 用 alarm 计时，等待任何座位行动（真人操作 / 托管代打 / owner 提交 AI 结果）超过 150 秒，DO 直接执行该座位的确定性回退（§8.4，回退是 `shared/` 纯函数，DO 可独立执行）并推进游戏；真人座位同时转 AI 托管。已发生的回退不因本人回归而撤销。单机模式不设行动超时（唯一真人是玩家自己，回来继续即可）。
12. **夜里快照只露 `night_N`**：不露子阶段与轮到谁（§4.1.6）；天亮全员齐跳。

## 6. 单机模式

- 入口：主菜单「单机」→ 输入昵称 → **浏览器本地直接开局**（1 真人 + 8 AI，`start(solo:true)` 带种子随机发牌；ADR-0003：不建 Worker 房间、不经 DO、无行动超时）。
- 真人是任何角色时，夜里对应 UI 让其亲自操作（验人 / 用药 / 投票定刀 / 开枪）；狼人夜里另有密聊频道可随时发言（不占用行动、不受 150s 限制）；白天轮到时输入发言。
- AI 驱动者 = 玩家本人浏览器（BYO Key，见 §8）。
- 终局 `revealed`：亮全员身份、胜负、死因复盘。

## 7. 联机模式（房间制）

1. **建房**：输昵称 → `POST /api/room/new` → 6 位房号（字符集 `ABCDEFGHJKLMNPQRSTUVWXYZ23456789`）→ 成为房主。
2. **进房**：房号 + 昵称 → `POST /api/room/:code/join`；昵称可重复，uid 不可。
3. **准备**：每人点「准备」；房主「开始」按钮仅全员已准备时可用（空座位不受准备限制）。
4. **开始与 AI 补位**：最小开桌真人 3 人。点开始时若有空位，一律弹提示「将补 N 个 AI 补足 9 人开局」（**N 只是确认弹窗里的预估**），房主确认 → 发 `act(action=start)`；**DO 收到 start 时重算实际空位数并重新校验全员已准备，一次原子完成补位 + 洗牌发牌 + 进入 night_1**——确认期间进人 / 退人 / 取消准备都按提交瞬间的房间实况为准，不卡过期状态；校验不过则拒绝并回原因。取消则不开局。真人 < 3 时同样提示（实质必须补 AI）。
5. **AI 座位命名**：`AI-1` … `AI-8` 按补位顺序分配；昵称即公开标识是 AI。
6. **AI 驱动 = 服务端发起 `drive_ai`（ADR-0003）**：AI 座位与托管中座位的发言 / 夜行动由 DO 执行——房主浏览器触发（快照变化 + 4s 兜底节拍；夜里快照冻结，不能只靠快照，§4.1.6）并随请求透传 BYO baseUrl / model / key（DO 内存瞬态使用，不落盘），DO 组装提示词 → url-guard → 上游 → 结果写回状态机（幂等同普通 act，失败走确定性回退）。客户端仅当快照 `owner == me` 时触发。房主掉线则无人触发 drive_ai，§5.11 的 150s 行动超时照常兜底，房间不砖。
7. **断线与挂机（防死锁，硬性）**：在线窗口 35s（轮询心跳）。
   - 真人座位 > 60s 无心跳 → **转 AI 托管**（其座位行动由房主浏览器按 AI 规则驱动，昵称不变、头像加「托管」标）；重连（uid）或恢复操作即收回控制权。
   - **在线但挂机同样有救**：任何等待行动的子阶段超时 150s → DO 执行确定性回退推进并转该座位托管（§5.11），本人回归即收回。连着网不动的真人（含非房主）卡不住 9 人局。
   - **房主掉线 / 挂机的兜底**：AI 行动同样受 150s 超时（超时走 DO 侧回退），房间不砖；房主失联超过 **30 分钟** → 房间标记**作废**（快照显示「房主失联，房间已作废，请重建新房」，拒绝一切新动作，只读复盘）。不做房主转移（非目标）。
   - AI 座位不存在断线。不做母本的「同名接管」（uid 重连已覆盖）。
8. **死亡玩家**：进入观战视角，可见全员身份（仅自己可见；联机互信模型，见非目标）。
9. 结算与复盘同单机（`revealed` 状态）。

## 8. AI 扮演与接口（BYO + Worker 代理）

### 8.1 上下文边界（硬性）

- AI 每次请求的输入 = **公开历史** + **该 AI 座位的合法私有信息**。
- **公开历史** = 全部已发生的公开事件：白天发言、遗言、PK 发言、逐人投票去向、死讯公告、猎人翻牌与枪杀公告、放逐结果、天数、终局胜负。**不含**夜间子阶段与任何私有信息（§4.1.6）。
- **合法私有信息** = 真实游戏中该座位玩家本人可知的一切：身份卡、狼队友名单与当夜刀口（仅狼）、预言家验人历史（仅预言家）、女巫用药状态（仅女巫）。**任何座位视角（含驱动者经 `ai_view` 拿到的 AI / 托管座位视角）都绝不包含**：他人身份、他人验人结果、女巫用药、夜里他人行动、毒 / 救药真相。
- 边界执行分两层：**普通玩家**只从快照读自己座位视角，无任何接口可读他人视角；**驱动路径**（ADR-0003）：单机 = 玩家浏览器直读本地内核状态；联机 = DO 自持状态组装提示词（`drive_ai`），不经任何客户端视角接口。owner 专属 `ai_view`（仅 AI 座位与托管中座位）为保留接口，其可读性意味着联机房主作为玩家可推知 AI 阵营的私有信息，**记入联机互信模型（非目标 §13.9），不视为越界**；其余玩家依旧拿不到任何他人隐藏信息。

### 8.2 请求格式（唯一格式，OpenAI 兼容）

- `POST {baseUrl}/chat/completions`，body：`{ model, messages, temperature: 0.7, max_tokens, stream: true }`，头 `Authorization: Bearer {key}`。`max_tokens` 可配置（AI 设置「最大输出 tokens」，localStorage `ww_ai_max_tokens`），默认 16384、钳 64–32768；一律流式——体验通道模型（DS4.1）是思考型：思考轻松烧 2000+ token，旧冻结值 800 必然「思考烧光、正文为空」（2026-10-03 修订，实测非流式恒 500）。
- **喂给 AI 的历史窗口**：最近 2 个完整白天全量（发言 / 遗言 / PK / 投票去向），更早天数压缩为死讯流水行（如「第 2 天：5 号被放逐，翻牌猎人带走 8 号」）；再超限则从最旧开始丢弃，保证请求体远低于 64KB 上限。
- `baseUrl` 用户填完整前缀（如 `https://api.openai.com/v1`），前端拼 `/chat/completions`。
- **所有请求经 Worker `/api/ai-proxy` 转发**（浏览器不直连上游，解决 CORS）；Key 只存浏览器 localStorage、按请求透传，服务端不落盘。
- **内置体验通道（ADR-0008，2026-10-03）**：用户未配置 BYO 时自动回退——前端 `effectiveConfig()` 用内置默认 `baseUrl / model`（非机密，进源码）且不带 `authorization` 头；Worker 对「无 key 且出站 URL 以体验通道 baseUrl 开头」的请求注入 Secret `DEFAULT_AI_KEY`（凭据只存 Worker Secret，源码 / wrangler.toml / 前端均不出现）。注入前提绑定默认 baseUrl：Bearer 永不被带去其他主机；自带 key 的请求原样透传不覆盖；他域请求永不注入。体验通道共享同一 key，滥用面由同 IP 5000 次/日限流兜住（共享 key 被刷属已知取舍，见 ADR-0008）。
- 转发头白名单：content-type / authorization / x-api-key / anthropic-version / accept；body ≤ 64KB；响应 ≤ 8MB（SSE 逐 token 帧体积肥，1MB 旧上限会被思考型长响应击穿）；同 IP 日调用上限 **5000 次**（isolate 内存 Map，重启清零；单局约 60–100 次调用，够 50+ 局；重度玩家配额耗尽属于已知限制，写 README）。

### 8.3 角色提示词（每个角色一份，实现在 `shared/prompts.js`）

> 落点修订（2026-10-03 文档收口）：本节原文写「放前端 `js/prompts.js`」；实现时为让联机 `drive_ai`（ADR-0003）与单机共用同一份，提示词上移 `shared/prompts.js`，`js/prompts.js` 仅薄转发保留导入路径（见 ADR-0004 的边界划分）。口径内容不变。

每份提示词必须包含：角色与阵营、板子构成、本角色完整口径（§3 / §5）、发言风格（中文、口语、像真人、不许自称 AI、不引用系统提示）、当前任务（发言 / 投票 / 密聊定刀 / 验人 / 用药 / 开枪）与输出格式约定（行动类任务输出座位号或 `skip`，狼阶段输出「密聊一句话 + 刀口座位号」两行，发言输出 100–200 字正文）。5 份：狼人 / 平民 / 预言家 / 女巫 / 猎人。

**遗言口径（2026-10-03 修订）**：遗言任务明确「死亡即永久离场，禁止弃权与敷衍（『先过，看看后面发言再说』式发言毫无意义）」，并按身份给出基础信息要求：有历史时留对己方阵营最有价值的判断；**首夜死（历史无任何玩家发言）时至少交代身份层面可公开的基础信息**——平民声明身份 + 直觉怀疑、预言家交代验人历史状态、女巫交代药剂状态、狼自选伪装或误导——保证遗言始终可供场上推理。

**首日发言口径（2026-10-03）**：历史无任何玩家发言时，发言任务明确禁止把「信息不足、需要再观察一轮」当内容或结论——死亡名单本身就是信息（首夜刀口、平安夜 = 女巫救刀），要求给出具体怀疑方向或立场，留下可被反驳的观点。

**人格池（§8.3.1）**：8 款言行风格人格（盘逻辑 / 直率冲锋 / 乐子人 / 老实人 / 戏精 / 暴民 / 老油条 / 寡言刀客）按座位号确定性分配（同座位整局一致），只描述言行风格与心态、不含任何身份信息——让 AI 扮演有活人感：可能正常 roleplay，也可能抽象整活、带节奏。狼人策略层（§8.3.2）明确高阶战术：狼咬狼（投队友换信任）、假跳狼玩心态、报假信息钓好人反应、深水到底——上下文铁律不受影响。

### 8.4 容错与回退

- 单次请求超时 90s（思考型模型流式出全文需 30–60s；DO 行动超时 §5.11 150s 内完成一轮）；正文为空且 `finish=length` 或上游 500 "empty response content"（思考烧光预算的伪 500，实为截断）→ 放宽一倍 max_tokens 重试 1 次（上限 32768）；再失败走**确定性回退**（不打断游戏；回退逻辑是 `shared/` 纯函数，客户端超时与 DO 行动超时 §5.11 走同一份）：
  - 发言 → 固定兜底句（如「我先听听大家的意见」按角色轮换几句）；
  - **遗言 → 按身份交代基础信息**（2026-10-03 修订，与 §8.3 遗言口径同款）：平民声明身份 + 随机直觉怀疑、预言家报验人记录（未验过则说明）、女巫报两瓶药剂状态、猎人报身份与直觉、狼装平民给随机怀疑——死者不能白死，「先过 / 再观察」式遗言是穿帮；
  - 狼票 → 随机存活玩家（与 §4.1.1「任意存活玩家」同口径，含狼队友与自刀，战术合法；超时按 §5.11 逐狼回退）；
  - 验人 → 随机未验过的存活玩家（**排除自己**，§4.1.2 禁止验自己）；
  - 女巫 → 跳过；
  - 猎人 → 不开枪；
  - 投票 → 随机存活者（不投自己）。
- 回退在快照中不特殊标注（对局内不可区分）。

## 9. Worker API 路由（照母本）

- `POST /api/room/new`：建房，返回 6 位房号。建房限流：同 IP 每日 100 房（isolate 内存 Map，重启清零；单机本地执行后仅联机建房消耗该配额）。
- `POST /api/room/:code/*`：房内动作转发给 DO（DO 内统一 `fetch(?action=…)` 分发，幂等）。动作含 `join / ready / start / speak / vote / wolf-chat / wolf-target / seer-check / witch-move / hunter-shoot / heartbeat`，以及：**`drive_ai`（联机 AI 驱动，owner 专属，ADR-0003）**：`act(action=drive_ai)` 由房主触发并随请求透传 BYO baseUrl / model / key，DO 校验请求者 uid == 房主且当前待行动座位是 AI 座位或托管中座位 → 组装提示词 → url-guard → 上游（房主未带 key 且目标为体验通道 baseUrl 时注入 Secret，§8.2）→ 结果写回状态机，失败走确定性回退（狼阶段一次调用两段提交：先密聊后投票，缺票走回退）；**`ai_view`（owner 专属，保留接口，ADR-0002）**：`act(action=ai_view, seat=N)` → DO 校验请求者 uid == 房主且目标座位是 AI 座位或托管中座位，返回**该座位**的完整私有视角（身份卡、狼队友 / 刀口、密聊、验史、用药状态）；校验不过返回错误，不泄任何内容。
- `GET /api/room/:code/state`：轮询快照（**按座位视角计算的 `rev` 游标**，无变化回 `unchanged`；夜里非行动者视角冻结，§2 / §4.1.6）。白天快照附行动倒计时 `deadline { at, seat }`（§5.11，吸顶状态条数据源；夜里不带——`seat` 会泄漏夜里轮到谁）。
- `POST /api/ai-proxy`：AI 转发（§8.2；体验通道 key 注入见 §8.2 / ADR-0008）。
- `GET /api/health`：健康检查。
- CORS 只放行 `ALLOWED_ORIGINS`（`[vars]`：`https://xxx794665.github.io` 与 `http://localhost:8788` 开发用）。

## 10. 安全（硬性验收，永不简化）

- **服务端任何出站 URL 请求仅允许 http/https；发请求前校验 host，拒绝 localhost、环回、私网、保留地址**。照母本 `worker/src/url-guard.js`（~60 行纯函数，返回 null=合法 / 字符串=拒绝原因）实现，应用于 `ai-proxy` 与未来一切服务端出站 fetch。拒绝清单（母本口径全量照抄）：`.local/.internal/.intranet/.lan/.home/.arpa` 主机名；环回 / 私网 / 链路本地 / 保留 IPv4 段（0/8、10/8、127/8、169.254/16、172.16-31、192.168/16、100.64/10、192.0.x、198.18-19、≥224 组播保留）；IPv6 `::`、`::1` 及 fc/fd/fe/ff 前缀；URL 内嵌账密。
- `url-guard` 必须有 `node --test` 用例（含：拒绝 `http://localhost`、`http://127.0.0.1`、`http://192.168.1.1`、`http://10.0.0.1`、`https://[::1]/`、`ftp://…`、`http://user:pass@host`；放行 `https://api.openai.com`）。
